# KeyMouse

Cross-platform global keyboard and mouse shortcut bindings for Node.js and Electron.

KeyMouse 是面向 Node.js / Electron 的跨平台全局键鼠快捷键绑定库。核心用途是让应用通过用户配置的键盘、鼠标按键或组合触发动作，即使应用在后台、没有焦点，也能响应绑定。

## 核心定位

围绕“配置绑定 → 匹配全局键鼠输入 → 触发动作”设计 API。全局事件监听和必要的选择性拦截是实现绑定的底层能力。

- 面向需要全局键鼠快捷操作的 Node.js / Electron 开发者。
- 支持用户配置单键或组合及多个绑定；首版具体按键范围和触发语义仍待确定。
- 区分监听与拦截：监听收到输入通知；拦截阻止原始输入继续传给其他应用。
- 明确报告平台能力和不支持的操作，避免静默降级。

左右修饰键、键鼠混合组合、长按、松开触发、重复触发及多普通键组合均需进一步确认，不默认全部纳入首版。

## 候选技术方案

候选结构：TypeScript 配置与业务 → Node-API → C++ 匹配与拦截引擎 → 平台输入后端。

目前评估 `uiohook-napi`、`libuiohook` 的复用与扩展，以及精简平台后端的自研方案，尚未定案。需要拦截时，拟由原生层根据预配置规则同步决定吞键或透传，再异步通知 JavaScript；不能依赖异步 JS 回调返回值决定原始事件去留。

## 平台边界

下表是已有调研中候选库的能力判断，不是 KeyMouse 的实测支持声明。

| 平台 | 调研结论 | 后续重点 |
| --- | --- | --- |
| Windows | 候选库支持监听，原生层存在拦截实现路径 | 权限边界、Hook 超时与恢复、事件配对 |
| macOS | 候选库支持监听，原生层存在拦截实现路径 | 授权、Secure Input、Event Tap 恢复 |
| Linux X11 | 候选库支持监听，XRecord 后端不能拦截 | 如需拦截，评估额外后端 |
| Linux Wayland | 候选库没有完整原生全局后端 | 评估 Portal 等受限能力，明确降级边界 |
